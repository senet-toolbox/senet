A SQL Editor application with the following exact specifications: Layout: Three-panel layout. Left sidebar (320px wide) with query history. Main area split vertically: top half is the SQL code editor, bottom half is the results area. Top bar with tab navigation for multiple open queries. Top Bar: Horizontal tab strip showing open query sessions. Each tab shows a truncated query name (e.g. "create table posts", "select all users", "query #5"). Active tab is visually distinct. Each tab has a close (×) button. Plus (+) button at the end to create a new empty query tab. Below the tabs on the left: three toggle buttons labeled [queries], [history], [schemas] to switch the sidebar content. SQL Editor Pane: Full code editor with line numbers on the left (1, 2, 3...). SQL syntax highlighting — keywords (CREATE, TABLE, SELECT, NOT NULL, DEFAULT, etc.) in distinct colors, string values in a different color, numbers in another. Monospace font throughout. A copy button in the top-right corner of the editor. The editor pane should be resizable vertically via a drag handle between editor and results. Results Area: Three tab buttons: [Results], [Chart], [Explain]. A "Check Memory" button and a "Submit ⌘+Enter" button on the right side. When Results is active: render a data table with typed column headers (e.g. "id int", "name string", "email string", "power int", "created_at datetime"). Each column header shows the column name and its type in a muted color. Table rows with alternating or clean row styling. Row selection via checkboxes on the left. The table should handle at least 20 rows with realistic sample data (use names like "Vic Rokx", "Goku", "Vegeta", "Piccolo", "Gohan", "Krillin", "Alicia" with emails, power levels as integers, and timestamps). Left Sidebar — History View: Shows a scrollable list of past queries, newest at top. Each history entry shows: a status indicator (green dot for successful queries showing row count like "18 rows" or "106 rows", red dot for errors showing "Error"), the SQL query text truncated to 2-3 lines, a timestamp (e.g. "20:37:23"), and if it's an error, a red error message below (e.g. "relation 'posts' already exists" or "insufficient data left in message"). Each history entry has three action buttons: Load, Save, Delete. Clicking Load populates the editor with that query. The currently selected history entry should be visually highlighted. Left Sidebar — Schemas View: When [schemas] tab is active, show a tree view of database tables with their columns and types. Functionality: Clicking Submit executes the query (simulate this — just show the results table with sample data or an error state depending on the query). Maintain separate state per tab — each tab has its own query text, results, and history. The editor should support Ctrl+Space for autocomplete (can be a placeholder). New tabs start with an empty editor. Switching tabs restores that tab's query and results. Styling: Clean, modern developer tool aesthetic. Dark theme for the code editor area, light theme for the rest. Monospace font (IBM Plex Mono or similar) for all code and table data. Blue accent color for active states and primary actions. Status colors: green for success, red for errors, yellow/orange for warnings.
